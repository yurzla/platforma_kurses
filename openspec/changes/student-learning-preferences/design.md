## Design

API использует аутентифицированного пользователя, не принимает `user_id` из клиента и выполняет
upsert по первичному ключу `user_learning_preferences.user_id`. Значения интересов и целей —
текст до 2000 символов; уровень — один из `beginner`, `intermediate`, `advanced` либо `null`.
Web-сервис получает значения при рендеринге `/my-courses` и отправляет форму через свой серверный
POST-маршрут, после чего перенаправляет пользователя обратно на страницу.
Поля расположены вертикально. Текстовые поля имеют высоту одной строки при пустом значении и
увеличиваются по `scrollHeight` при вводе или загрузке сохранённого многострочного текста.
Блок настроек отделён от последующего поиска внешним отступом.
Заголовок блока предпочтений в интерфейсе — «Обо мне».

При запросе рекомендации система дополняет текст вопроса непустыми интересами, целями и уровнем
текущего пользователя перед созданием временного embedding. Этот embedding не сохраняется;
векторизованные описания опубликованных курсов остаются индексом поиска.
Названия и описания завершённых пользователем курсов также дополняют поисковый текст, а сами эти
курсы исключаются из кандидатов. Курсы со статусом `in_progress` не исключаются.
