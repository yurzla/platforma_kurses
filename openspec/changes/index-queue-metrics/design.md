# Design

## Проблема семантики

`XLEN rag.index.requests` — это ретенция стрима: сообщения не удаляются по `XACK`, только
триммингом по `MAXLEN`. Поэтому `length` не равен размеру очереди.

Правильная «очередь» = `pending` (доставлено, не подтверждено) + `lag` (ещё не доставлено).
`XINFO GROUPS` отдаёт оба значения; при отсутствии группы они `null`.

## Решение

- В `IndexQueueState` добавляется вычисляемое поле `queue_size: int` =
  `(pending or 0) + (lag or 0)`. Вычисляется на сервере, чтобы и API, и UI трактовали «очередь»
  одинаково.
- Поля `length`, `pending`, `lag`, `consumers`, `dead_letters` сохраняются для обратной
  совместимости.
- UI: карточка «в очереди на индексацию» показывает `queue_size`; отдельная карточка «сообщений в
  стриме» показывает `length`; «отставание индексатора» остаётся `lag`; ошибки — `dead_letters`.
- Таблица Streams: заголовок `Length (всего)` и пояснение в описании вкладки, что длина включает
  уже обработанные сообщения, а `Pending`/`Lag` показывают реальную работу очереди.

## Риски

- `queue_size` зависит от наличия consumer group: без группы `pending`/`lag` = `null`, тогда
  `queue_size = 0`, а `length` покажет накопленные сообщения — это ожидаемое поведение (никто не
  обрабатывает стрим).
- Изменение только аддитивное, старые клиенты не ломаются.
