## Context

См. `proposal.md` — Why. Текущий `static/dashboard.css` задаёт только тёмную палитру через CSS-переменные в `:root`; HTML рендерится Jinja2 (`base.html` + `dashboard.html`).

## Goals / Non-Goals

**Goals:**
- Переключение light/dark без новых зависимостей и без «мигания» при загрузке.
- Персистентность выбора и учёт системной темы по умолчанию.
- Одинаковое поведение на дашборде и странице входа.

**Non-Goals:**
- Серверное хранение темы (cookie/профиль).
- Дополнительные темы/кастомизация палитры.
- Тема для Swagger UI.

## Decisions

**1. Тема на CSS-переменных + атрибут `data-theme` на `<html>`.**
Тёмная палитра остаётся в `:root` (дефолт), светлая — в `:root[data-theme="light"]`. Статусные цвета вынесены в переменные. Альтернативы: отдельные CSS-файлы (лишние загрузки), дублирование правил.

**2. Хранение в `localStorage`, дефолт — `prefers-color-scheme`.**
Клиентское, без серверного состояния. inline-скрипт в `<head>` выставляет `data-theme` до первой отрисовки (без FOUC). Альтернатива — cookie темы на сервере: избыточно.

**3. Общий `static/theme.js` для дашборда и логина.**
Инициализация и обработчик кнопки по селектору `[data-theme-toggle]`; `base.html` подключает скрипт, конкретные страницы только добавляют кнопку.

## Risks / Trade-offs

- `color-mix()` в CSS для прозрачных бейджей — поддержка в современных браузерах; для старых допустима деградация к сплошному фону.
- Тема не синхронизируется между устройствами (localStorage) → приемлемо для внутреннего инструмента.
