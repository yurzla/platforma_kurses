# Design

## Context

`users.password_hash` — обязательное TEXT-поле. Сейчас в нём лежит строка
`scrypt$<salt>$<digest>`, проверка выполняется через `hashlib.scrypt`. Ключ
подписи JWT уже берётся из настроек, поэтому секрет паролей логично держать
рядом — в `.env`.

## Goals / Non-Goals

**Goals:**

- Обратимое шифрование паролей ключом из `.env`.
- Понятная ошибка, если ключ не задан.
- Массовая выдача новых паролей существующим пользователям.
- Логины и пароли — в отдельном незакоммиченном файле.

**Non-Goals:**

- Не меняем схему БД и имя колонки `password_hash`.
- Не добавляем API для просмотра паролей.
- Не храним ключ в репозитории, образе или файле с паролями.

## Decisions

1. **Fernet из `cryptography`.** Аутентифицированное шифрование AES-CBC+HMAC,
   готовый формат токена. Префикс `fernet$` отделяет новый формат от старых
   `scrypt$` значений.
2. **Ключ в `PASSWORD_KEY`.** `Settings.password_key` читается из `.env`;
   `resolved_password_key()` падает с понятным сообщением, если ключ пуст.
   Ключ запрашивается только в операциях с паролями, поэтому worker/cron/
   scheduler не требуют его при старте.
3. **Файл паролей отдельно от ключа.** `.secrets/passwords.txt` содержит
   только `email<TAB>password`; ключ остаётся в `.env`. Каталог `.secrets/`
   добавлен в `.gitignore`, файл пишется с правами `600`.
4. **Сброс через скрипт.** `reset_passwords` генерирует пароли, шифрует их
   текущим ключом, удаляет refresh-токены и атомарно пишет файл. Повторный
   запуск перегенерирует пароли тем же ключом.

## Risks / Trade-offs

- [Обратимое шифрование слабее хеширования] → компромисс; ключ хранится
  только в `.env`, файл паролей — вне git, права `600`.
- [Потеря `PASSWORD_KEY` делает пароли нечитаемыми] → ключ нужно сохранить
  отдельно; при утере потребуется повторный сброс.
- [Деплой без сброса заблокирует вход] → сброс выполняется частью выката,
  старые `scrypt$` значения намеренно не принимаются.

## Migration Plan

1. Сгенерировать `PASSWORD_KEY` и добавить в локальный `.env`.
2. Выполнить `reset_passwords` — пароли в БД перезаписываются, файл с новыми
   паролями создаётся в `.secrets/`.
3. Перезапустить API. Откат — вернуть предыдущий коммит и восстановить пароли
   из резервной копии БД.
