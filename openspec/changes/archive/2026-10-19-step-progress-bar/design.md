## Context

`pages.py` уже умеет считать прогресс курса для страницы курса (`_course_progress`: `done`,
`total`, `percent`, `next_href`), а страница шага уже загружает полную структуру курса — значит,
прогресс и границы модулей можно посчитать без новых запросов к API.

## Goals / Non-Goals

**Goals:**
- Показать прогресс всего курса на странице шага.
- Отметить границы модулей на шкале как контрольные точки с подсказками.
- Обновлять прогресс после отметки шага без перезагрузки.

**Non-Goals:**
- Изменение API прогресса или схемы БД.
- Переход по клику на контрольную точку к модулю.
- Прогресс по урокам/заданиям внутри модуля и отдельные полосы для модулей.

## Decisions

- **Прогресс считает существующий `_course_progress`.** Он проходит `sections → lessons → steps`
  и учитывает все шаги курса; на шаге вызывается с уже загруженной структурой курса.
- **Контрольные точки — кумулятивные границы секций.** Для каждой секции со шагами позиция =
  число шагов до конца секции / общее число шагов. Последняя граница совпадает с концом шкалы,
  поэтому не рисуется; подсказка — «Модуль: N из M шагов» по самой секции.
- **Разметка шкалы — один div с заливкой и абсолютными тиками.** `role="progressbar"` с
  `aria-valuenow`; тики `position: absolute; left: %` и `title` для нативного тултипа.
- **Обновление после отметки — на клиенте.** В `window.STEP_PROGRESS` передаются `done` и `total`;
  после успешного `POST .../answer` JS увеличивает `done`, пересчитывает процент и обновляет
  ширину заливки, `aria-valuenow` и подпись.

## Risks / Trade-offs

- [Много модулей — тики сливаются] → тики тонкие, а подсказки дают названия; при большом числе
  секций шкала остаётся читаемой как общая полоса.
- [Шаг уже был выполнен, но кнопка недоступна] → инкремент выполняется только в обработчике
  успешной отметки, поэтому двойного счёта нет.
- [Завершённый шаг мог быть перепройден] → API идемпотентен, но повторной отправки из UI нет.
