## Context

`DELETE /api/v1/chat/sessions/{id}` удаляет одну сессию, которую предварительно надо открыть или
найти в истории. История панели строится из `GET /api/v1/chat/sessions` и на странице курса
фильтруется по `course_id`; на `/courses` и `/my-courses` показываются все сессии пользователя.

## Goals / Non-Goals

**Goals:**
- Очистить историю одним действием и одним запросом.
- Не удалять чужие сессии и не оставлять осиротевшие `jobs`.
- Удалять только то, что пользователь видит: на странице курса — сессии этого курса, на списках
  курсов — всю историю.

**Non-Goals:**
- Изменение прав: удалять можно только свои сессии (admin-режим для массовой очистки не нужен).
- Мягкое удаление/корзина, восстановление, экспорт перед удалением.
- Отдельный счётчик удалённых сессий в ответе.

## Decisions

- **Один эндпоинт `DELETE /api/v1/chat/sessions?course_id=`.** Возвращает `204` без тела, как
  одиночное удаление. `course_id` необязателен: без него удаляются все сессии пользователя.
- **Сначала `jobs`, потом сессии.** У `jobs.session_id` нет `ON DELETE CASCADE`, поэтому роутер
  получает id сессий (`list_session_ids`), удаляет job-ы пачкой (`delete_by_sessions`) и только
  затем сессии (`delete_sessions`); сообщения уходят каскадом.
- **Порты расширяются, а не дублируются.** `ChatRepository` получает `list_session_ids` и
  `delete_sessions`, `JobRepository` — `delete_by_sessions(ids)`; фейки обновляются вместе с
  портами.
- **Кнопка в шапке истории.** «Очистить историю» рендерится партиалом `_assistant_history.html`
  только когда история непуста, поэтому после очистки кнопка исчезает вместе со списком. Запрос
  идёт через web-прокси с `?course_id=` при открытой странице курса.
- **Ширина кнопки удаления — 40 px.** Иконка увеличивается до 18 px; строка истории уже сжимается
  (`min-width: 0`), поэтому переполнения нет.

## Risks / Trade-offs

- [Массовое удаление необратимо] → обязательное подтверждение в UI; API без подтверждения, как и
  одиночное удаление.
- [Долгая транзакция при большом числе сессий] → удаление идёт двумя SQL-запросами (`jobs`, затем
  сессии), без поштучных вызовов на реальной БД.
- [Пользователь на странице курса ожидает глобальную очистку] → кнопка ограничена тем же
  `course_id`, что и список истории; подтверждение уточняет формулировку.
