## Context

См. `proposal.md` — Why. Сейчас доступ защищён единым `ADMIN_TOKEN` (`dependencies.py`, `routers/dashboard.py`), проверяемым из заголовка, cookie или query-параметра. В БД есть таблица `users` с `password_hash`/`role`, но в демо-дампе только 3 пользователя с ролью `student` и заглушечным `password_hash='x'` — администраторов нет.

## Goals / Non-Goals

**Goals:**
- Удобный вход по логину/паролю с сессией для дашборда и админ-API.
- Сохранить возможность открытого доступа в локальной разработке (пустые креды).
- Минимум новых зависимостей и никаких изменений схемы БД.

**Non-Goals:**
- Управление пользователями, роли, регистрация, смена пароля из UI.
- Хранилище сессий на сервере (используется stateless-подпись cookie).
- Внешний провайдер идентификации (SSO/OIDC).

## Decisions

**1. Креды из переменных окружения (`ADMIN_USERNAME`/`ADMIN_PASSWORD`), а не из БД.**
В дампе нет админов и нет валидных хэшей паролей, поэтому БД-вариант требует отдельного scheme хэширования, миграции и сидинга. Env проще и достаточно для внутреннего инструмента. Альтернатива (таблица `users`, `role='admin'`) отложена.

**2. Сессия — подписанная cookie через Starlette `SessionMiddleware` (`itsdangerous`).**
Stateless, стандартно, без серверного хранилища. Альтернативы: HTTP Basic (нет отдельной формы и «выхода», пароль в каждом запросе), JWT (лишняя зависимость/сложность). Cookie: `HttpOnly`, `SameSite=Lax`, `https_only=ADMIN_COOKIE_SECURE`.

**3. `ADMIN_SESSION_SECRET` опционален; при отсутствии выводится из логина/пароля.**
Удобно для локалки (одна переменная меньше). Смена пароля инвалидирует сессии — приемлемо.

**4. Разное поведение для HTML и API.** `require_admin_page` редиректит на `/login?next=…` (307), `require_admin` для API возвращает `401`. JS дашборда при `401` сам уходит на `/login`.

**5. Защита от open-redirect.** Параметр `next` принимается только как локальный путь (начинается с `/` и не `//`).

**6. Пустые креды → доступ открыт.** Сохраняем текущую эргономику локальной разработки; при заданных `ADMIN_USERNAME` и `ADMIN_PASSWORD` вход обязателен.

## Risks / Trade-offs

- Сервис по HTTP: cookie без `Secure` (по умолчанию) → включать `ADMIN_COOKIE_SECURE=true` за TLS.
- Stateless-сессия нельзя отозвать до истечения/смены секрета → малый `ADMIN_SESSION_MAX_AGE` (12ч) и смена секрета как механизм отзыва.
- CSRF: эндпоинты read-only, login/logout с `SameSite=Lax`; риск минимален.
- Добавлены зависимости `itsdangerous`, `python-multipart`.
