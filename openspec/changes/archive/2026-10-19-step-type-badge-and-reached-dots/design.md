## Context

`StepRead` возвращает поле `step_type`, а шаблон страницы шага обращался к `step.type`: бейдж
рендерился пустым, а условие `step.type == "choice"` всегда ложно. Прогресс-бар уже знает
позиции контрольных точек в шагах, но не их достижимость.

## Goals / Non-Goals

**Goals:**
- Показать тип шага подписью на русском.
- Выбирать форму ответа по `step_type`.
- Подсвечивать достигнутые точки прогресса синей обводкой, в том числе после клиентского
  обновления прогресса.

**Non-Goals:**
- Новые типы заданий и их формы (matching/sorting/code остаются как есть — текстовый ввод или
  ручная отметка).
- Изменение API шага.
- Анимация появления обводки.

## Decisions

- **Подписи типов — словарь в шаблоне.** Переиспользуем тот же набор, что на странице курса
  (`choice` → «Тест», `text` → «Текст», `code` → «Код», …); неизвестный тип выводится как есть.
- **Условие формы — `step.step_type`.** Это чинит и бейдж, и рендер вариантов ответа.
- **Достижимость точки считается по числу шагов.** Каждая точка хранит кумулятивный номер шага
  (`step`) и получает `reached = step <= done`; сравнение по процентам не используется, чтобы
  избежать расхождений округления (33.33 против 33.3).
- **Клиентское обновление — по `data-step`.** После отметки шага JS увеличивает `done` и
  переключает `reached` у точек, у которых `data-step <= done`.
- **Обводка — `box-shadow`.** У обычных точек синее кольцо, у жирных — синее кольцо с зазором
  цветом фона, чтобы не сливаться с крупной точкой.

## Risks / Trade-offs

- [Синяя обводка на синей заливке] → точки имеют светлый фон/контрастный цвет, а у модульных
  есть зазор цветом панели.
- [Неизвестный тип шага] → бейдж покажет исходную строку, форма останется ручной отметкой.
