# Design

## Context

Тело шага хранится в `step_contents.body` и отдаётся API как есть. Web-слой
выводит его через `{{ step.body | safe }}`. Импортированные из Stepik шаги
содержат полноценный HTML, включая `<iframe>` с видео.

## Goals / Non-Goals

**Goals:**

- Новые шаги удобно писать в Markdown.
- Переносы строк сохраняются.
- Импортированный HTML отображается ровно как раньше.

**Non-Goals:**

- Не меняем хранение в БД и API.
- Не переводим описания курсов на Markdown.
- Не добавляем WYSIWYG-редактор.

## Decisions

1. **Рендеринг в web-слое.** Это презентационное поведение; web-пакет получает
   зависимость `markdown-it-py`, backend и API не меняются.
2. **`markdown-it-py` с `html=True` и `breaks=True`.** CommonMark плюс
   сохранение одиночных переносов строк и пропуск инлайн-HTML.
3. **Определение унаследованного HTML.** Если в теле есть блочный HTML-тег в
   начале строки (`<p>`, `<div>`, `<h1..6>`, `<ul>`, `<ol>`, `<table>`,
   `<iframe>`, `<pre>`, `<blockquote>`, `<img>`, `<video>` и т.п.), тело
   отдаётся без Markdown-обработки. Так импорт не ломается и не требует
   миграции контента.
4. **Jinja-фильтр `markdown`.** Возвращает `Markup`, чтобы шаблон не применял
   повторное экранирование.

## Risks / Trade-offs

- [Смешение Markdown и блочного HTML в одном шаге] → такие шаги рендерятся как
  HTML; для нового контента достаточно Markdown.
- [Markdown может изменить вид старых «plain text» шагов] → изменения
  минимальны и соответствуют ожидаемому поведению Markdown; HTML-шаги
  защищены эвристикой.
- [Безопасность] → HTML по-прежнему разрешён, как и раньше; контент создаёт
  преподаватель.

## Migration Plan

Миграции БД не нужны. Откат — revert коммита.
