## Context

`build_sources_section` фильтровал курсы по упоминанию в тексте ответа, из-за чего ответы по материалам оставались без «Источников», если модель не назвала курс. Требование — в каждом ответе со ссылками на источники, а для списка рекомендаций — компактное описание.

## Goals / Non-Goals

- Goals: секция «Источники» почти всегда; корректная дедупликация; короткое описание в рекомендациях.
- Non-Goals: изменение набора рекомендаций/эмбеддингов; жирность ссылок (остаётся как есть); персонализация.

## Decisions

### Источники: все retrieved-курсы vs упоминание
`build_sources_section(courses, *, answer=None)` — при `answer=None` перечисляются все курсы (RAG-ответ и рекомендательный список), при заданном `answer` — только упомянутые (ответ по каталогу без чанков). Фильтр по упоминанию остаётся только для ветки «ответ по каталогу», где источников-чанков нет и единственный разумный якорь — сам текст ответа.

Альтернатива (всегда все курсы) отвергнута: в ответе по каталогу это вывалило бы весь каталог в «Источники».

### Ветки добавления секции в `process_question`
- `source_courses` непусты (есть чанки) → секция со всеми курсами-источниками.
- чанков нет, но есть `catalog_links` (глобальная сессия) → секция из упомянутых курсов каталога.
- рекомендательная ветка (ранний `return`) → секция из рекомендованных курсов.
- «нет материалов» (`NO_MATERIALS_ANSWER`) → без секции.

### Формат рекомендаций
Краткое описание — `recommendation_description_limit` (default 120) в `Settings` + `RECOMMENDATION_DESCRIPTION_LIMIT`. Пункты разделяются пустой строкой (`"\n\n".join`), заголовок тоже отделяется пустой строкой от первого пункта.

## Risks / Trade-offs

- [Дублирование] Рекомендательный ответ перечисляет курсы дважды (список + «Источники») — принято по решению пользователя.
- [Пустая секция] Если в RAG-ответе курсы-источники без `course_id`, секция не добавляется (нечего ссылать).

## Migration Plan

Без миграций БД. Поведение меняется только у вновь генерируемых ответов.
