## Context

Ответы ассистента приходят в браузер как обычный текст JSON и вставляются через `textContent`,
поэтому Markdown-разметка видна как есть. Проект использует vanilla-JS без сборщика и внешних
библиотек, поэтому форматирование делается небольшим собственным рендерером.

## Goals / Non-Goals

**Goals:**
- Показывать жирный текст и код (блоком в рамке, инлайн в рамке) в ответах ассистента.
- Сохранять переносы строк и не интерпретировать HTML из ответа модели (безопасность).

**Non-Goals:**
- Полноценный Markdown (заголовки, таблицы, ссылки, списки).
- Подсветка синтаксиса.
- Форматирование сообщений пользователя.

## Decisions

- Отдельный статический файл `assistant-format.js` с чистой функцией
  `window.renderAssistantAnswer`, подключается перед `web.js`. Альтернатива (инлайн в `web.js`)
  усложняет тестирование и переиспользование.
- Сборка DOM через `createElement`/`createTextNode`/`createDocumentFragment` вместо `innerHTML` —
  исключает XSS из ответа модели.
- Поддерживаемая разметка минимальна: `**жирный**`, `` `инлайн` ``, блоки в тройных бэктиках.
- В `SYSTEM_PROMPT` добавлено правило оформлять ответ в Markdown, чтобы код приходил в блоках.

## Risks / Trade-offs

- Модель может использовать Markdown, который рендерер не понимает (заголовки, таблицы) — они
  останутся обычным текстом, это приемлемо.
- Незакрытый блок кода остаётся текстом — рендерер его не съедает.
- Инлайн жирный внутри блоков кода не обрабатывается — код остаётся кодом.
