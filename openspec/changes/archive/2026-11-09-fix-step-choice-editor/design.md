# Design

## Context

Форма шага рендерится через `_step_form.html`. Все подписи внутри формы
получают `.step-form label { display: flex; flex-direction: column; }`, а
строка варианта — класс `.choice-editor` с `display: grid`. Селектор
`.step-form label` имеет специфичность (0,1,1) и перебивает `.choice-editor`
(0,1,0), поэтому чекбокс и поле варианта встают в колонку.

Создание шага идёт через web-маршрут `POST /teacher/lessons/{lesson_id}/steps`.
В `pages.py` над функцией `_step_payload` остался декоратор того же маршрута.
FastAPI регистрирует эту функцию как обработчик первой; параметр
`form: dict[str, str]` трактуется как JSON-тело, а форма приходит
urlencoded-строкой — Pydantic возвращает 422 с `Input should be a valid
dictionary`.

## Goals / Non-Goals

**Goals:**

- Вернуть строкную раскладку вариантов теста.
- Восстановить создание шага через web-форму.
- Закрепить оба поведения тестами.

**Non-Goals:**

- Не меняем API, схемы, БД и логику валидации шагов.
- Не меняем остальную вёрстку формы.

## Decisions

1. **Уточнить селектор раскладки.** Использовать
   `.step-form .choice-editor` (0,2,0) и `.step-form .multiple-choice`, чтобы
   правила формы не перебивали строкную раскладку.
2. **Удалить лишний декоратор.** `_step_payload` остаётся обычной функцией;
   единственный маршрут создания — `teacher_create_step`.
3. **Регрессионный тест на маршруты.** Проверять таблицу маршрутов web-роутера:
   для пути создания шага зарегистрирован только `teacher_create_step`.

## Risks / Trade-offs

- [Тест на таблицу маршрутов связан с именами функций] → это внутренний
  web-роутер, имя стабильно и явно отражает назначение обработчика.
