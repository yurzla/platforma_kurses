## Context

См. `proposal.md`. Страница курса рендерится `web/src/courses_web/templates/course.html` из контекста `routers/pages.py::course()`, который кладёт `me`, `course`, `course_id`. Ответ `GET /api/v1/courses/{id}` (`CourseDetailRead`) отдаёт `sections[] → lessons[] → steps[]` с полем `completed` на шаге, но без агрегированного прогресса. Описания в БД — одна слитная строка: `load_stepik.clean_text` удаляет HTML-теги и схлопывает все пробелы, включая переносы. `static_url` версионирует статику, `base.html` подключает `web.js` на страницах курса/шага.

## Goals / Non-Goals

**Goals:**
- Двухколоночная страница курса с закреплённым левым блоком: прогресс + переключатель «Описание/Содержание».
- Прогресс, вычисляемый без изменения API/БД.
- Читаемое описание с сохранёнными абзацами/переносами.
- Аккордеоны модулей/уроков без внешних зависимостей.

**Non-Goals:**
- Изменение `CourseDetailRead`, backend-роутеров или схемы БД.
- Хранение состояния выбранной вкладки между перезагрузками.
- Изменение страницы шага и виджета ассистента.

## Decisions

- **Прогресс считается в `course()` из структуры курса** (`total`, `completed`, `percent`, `next_href`). Альтернатива — расширить `CourseDetailRead`; отклонена, чтобы не менять API и `learning-catalog` и не синхронизировать логику с `recompute_course_progress`. Расхождение возможно только если в курсе есть выключенные шаги; сейчас импорт создаёт все шаги включёнными.
- **Вкладки — маленький `static/course.js`** (`role=tab`, `aria-selected`, по умолчанию «Содержание») поверх серверной разметки. Обе панели присутствуют в HTML, поэтому без JS видны обе (деградация). Альтернатива — CSS `:has()` без JS; JS выбран ради доступности и предсказуемости.
- **Аккордеоны — нативные `<details>/<summary>`** для модулей и уроков: сворачивание без JS и внешних библиотек.
- **Счётчики модулей/уроков и мини-прогресс считаются в Jinja** через `selectattr`/`sum`, чтобы не менять форму данных.
- **Описание рендерится как экранированный текст с `white-space: pre-line`**, а импорт сохраняет переносы (`clean_description`): до удаления тегов `</p>`, `<br>` и блочные закрывающие теги заменяются на `\n`, HTML-сущности разэкранируются, пробелы внутри строк схлопываются, пустые строки ограничиваются одной. `clean_text` (для эмбеддингов и прочих полей) не трогаем.
- **Стили — в `web.css`** на существующих CSS-переменных темы; раскладка `grid`, сайдбар `position: sticky`, на узких экранах — одна колонка.

## Risks / Trade-offs

- [Старые данные без переносов] → описания появятся после переимпорта (`load_stepik`); до этого страница показывает улучшенную типографику одного абзаца.
- [Прогресс на веб-слое может разойтись с `enrollments.progress_percent` при выключенных шагах] → сейчас таких шагов нет; проверка в тестах на структуре API.
- [`<details>` не сообщает состояние в HTML-тесте] → тесты проверяют наличие тегов/заголовков и счётчиков, а не раскрытие.
- [FAB ассистента в левом нижнем углу] → на узких экранах сайдбар не фиксирован по высоте, наложение маловероятно; при необходимости правится в CSS.

## Migration Plan

1. Задеплоить код.
2. Переимпортировать курсы: `uv run python -m courses_assistant.scripts.load_stepik --dump-dir stepik_dump`; при необходимости пересчитать эмбеддинги `embed_chunks`.
3. Откат — предыдущая версия кода; данные совместимы (переносы в тексте не ломают API).
