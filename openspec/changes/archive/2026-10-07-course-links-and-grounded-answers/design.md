## Context

См. `proposal.md — Why`. Текущий поток ответа: `application/handlers.py::process_question`
переписывает вопрос, при глобальной сессии подмешивает текстовый каталог
(`domain/prompts.py::build_course_catalog`), извлекает чанки (`CourseChunkRepository.search`)
и генерирует ответ. `RetrievedChunk` не несёт курс, контекст (`domain/context.py`) не указывает
курс, ссылок нигде нет, а `web/src/courses_web/static/assistant-format.js` рендерит только
жирный/код. Страницы курсов — `/courses/{id}`.

## Goals / Non-Goals

**Goals:**
- Ограничить ответы материалами курсов из БД и каталогом портала.
- Вшивать Markdown-ссылку на релевантный курс и гарантировать её наличие.
- Рекомендовать только курсы каталога, с ссылками.
- Безопасно рендерить ссылки портала в web-панели.

**Non-Goals:**
- Изменение схемы БД, Alembic-миграции, публичного контракта API.
- Показ ссылок/кнопок вне текста ответа (структурные поля UI).
- Тестирование JS-рендера фреймворком (в проекте нет JS-тестов).

## Decisions

- **Ссылки — относительные пути `/courses/{id}`.** Работают в браузере на web-портале; API
  отдаёт их как часть текста. Альтернатива (абсолютные URL, базовый адрес) отклонена: лишняя
  настройка и ломка между средами.
- **Детерминированная гарантия ссылки в backend.** Чистая функция `ensure_course_link(answer,
  links)` дописывает `Подробнее: [«Title»](/courses/{id})` для релевантных курсов, которых нет
  в ответе (проверка `"/courses/{id}" in answer`). Альтернатива — полагаться только на промпт —
  отклонена: модель может опустить ссылку.
- **Релевантные курсы:** для сессии по курсу — текущий курс; для глобальной — уникальные курсы
  найденных чанков; при рекомендациях — записи каталога. Названия берём из чанков, а для курса
  сессии — через новый лёгкий `CatalogRepository.get_course_summary(course_id)`.
- **`RetrievedChunk` расширяется `course_id`/`course_title`** (с дефолтами `None`) — обратная
  совместимость тестов и фейков. SQL-search делает join `CourseORM`.
- **Промпт-харденинг** в `SYSTEM_PROMPT`: только материалы + каталог, запрет внешних знаний,
  обязательная Markdown-ссылка на курс, рекомендации только из каталога с точной ссылкой.
- **Web-рендер ссылок — только относительные пути** (`^/...`, без схемы и `//`), сборка через
  `createElement('a')`/`textContent` (XSS-безопасно, как сейчас). Внешние ссылки — плейнтекстом.
  Альтернатива — общий Markdown-парсер — отклонена: лишняя зависимость и риск безопасности.

## Risks / Trade-offs

- [Модель добавляет лишние/вымышленные ссылки] → рендер пропускает только относительные пути;
  невалидные показываются текстом; промпт ужесточён.
- [Двойная ссылка, если модель уже вставила] → дедуп по `"/courses/{id}"` перед дописыванием.
- [Дополнительный запрос названия курса] → лёгкий `get_course_summary` без загрузки структуры.
- [global-ответ без чанков и без рекомендаций] → если релевантных курсов нет, ссылку не
  добавляем (нет основания); сообщение об отсутствии материалов сохраняется.
