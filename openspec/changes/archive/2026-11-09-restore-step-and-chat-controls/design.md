# Design

## Context

`Refac-architecture` (`208a2f0`) уже является предком текущей ветки, поэтому
`git merge` ничего не переносит. Исходная реализация сохранена в истории:

- `12a95e3` — API удаления/выгрузки диалогов, web-кнопки и шрифт PDF;
- `c160faf` — модальное подтверждение удаления;
- `8cdf2e5` — навигация по шагам и состояние «Выполнено»;
- `83034ba` — прогресс-бар, точки модулей и исправление refresh-cookie;
- `7d9ce95`, `b01131b`, `208a2f0` — крошки, подписи типов и стили точек.

Спеки `web-interface` и `rag-chat` уже содержат нужные требования. Задача —
вернуть реализацию, сохранив более новые изменения текущей ветки.

## Goals / Non-Goals

**Goals:**

- Вернуть четыре пользовательские функции из Refac без отката текущих фич
  (кабинет преподавателя, форматирование ответов ассистента, нейтральные
  сообщения об ошибках, импорт вариантов ответа).
- Сохранить совместимость с существующими контрактами API и тестами.

**Non-Goals:**

- Не менять требования в `openspec/specs/`.
- Не трогать БД, миграции и модели вариантов ответа.
- Не рефакторить кабинет преподавателя и административную панель.

## Decisions

1. **Восстанавливать вручную, а не cherry-pick.** Коммиты Refac частично
   перекрыты более новыми правками (`web.js`, `web.css`, `pages.py`).
   Cherry-pick даст конфликты, которые всё равно придётся разрешать вручную;
   точечное восстановление проще проверить тестами.

2. **Backend-роуты копируются из `208a2f0`.** `chat_export.py`,
   `adapters/export/pdf.py`, порты, реализации репозиториев и фейки уже на
   месте, поэтому в `routers/chat.py` возвращаются только три обработчика и
   импорты. Зависимость `fpdf2` возвращается в `backend/pyproject.toml`;
   записи в `uv.lock` сохранились.

3. **Страница шага восстанавливается целым кластером.** Шаблон, контекст
   `pages.py` и CSS берутся из `208a2f0`: это согласованный набор, на который
   уже написаны тесты. Текущее экранирование `choice.text` сохраняется, потому
   что это осознанная правка текущей ветки.

4. **Навигация всегда видима.** Текущая скрытая «Далее» заменяется на
   постоянные «← Назад» / «Вперёд →», как требует спека. Вместе с ней из
   `pages.py` убирается ставший ненужным `_next_step_url`.

5. **`web.js` объединяется вручную.** От Refac возвращаются
   `updateStepProgress`, состояние «Выполнено», экспорт, удаление и модалка.
   От текущей ветки сохраняются `renderAssistantAnswer`, try/catch вокруг
   запросов и нейтральный текст ошибок.

6. **Конфликт `.btn.danger` решается scoped-правилом.** Текущая ветка оформила
   `.btn.danger` как контурную кнопку преподавателя. Красная кнопка модалки
   получает правило `.confirm-actions .btn.danger`, чтобы не перекрашивать
   кабинет преподавателя.

7. **Refresh-cookie.** В `call_api` возвращается подстановка
   `request.state.merged_cookie`, иначе второй запрос страницы шага после
   refresh уходит со старым access-токеном и прогресс рендерится как `0 из 0`.

## Risks / Trade-offs

- [Расхождение текущего и Refac-кода в `web.js`/`web.css`] → Слияние вручную,
  целевые web-тесты и полный прогон `make test-unit`.
- [Отсутствие `fpdf2` в окружении] → Вернуть зависимость, проверить
  `uv lock --check` и `uv run pytest tests/unit/test_chat_export.py`.
- [Дублирование логики экспорта] → Использовать уже существующие
  `application/chat_export.py` и `adapters/export/pdf.py`, не создавать новые.

## Migration Plan

Миграции не нужны. Откат — обычный `git revert` коммита восстановления.
