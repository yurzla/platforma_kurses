## Context

Страница шага (`/courses/{course_id}/steps/{step_id}`) получает данные шага из API и уже
загружает структуру курса для заголовка. Шаги в структуре идут секции → уроки → шаги, и именно
этот порядок используется на странице курса и в «Продолжить».

## Goals / Non-Goals

**Goals:**
- Переход к соседнему шагу в порядке курса без возврата к содержанию.
- Неактивные кнопки на первом и последнем шаге.
- Однозначное состояние выполнения: «Отметить выполненным» → зелёная неактивная «Выполнено».

**Non-Goals:**
- Изменение API шага (соседи вычисляются в web из уже загруженной структуры курса).
- Навигация стрелками клавиатуры, свайпы, автопереход после ответа.
- Изменение автопроверяемых шагов: у них нет кнопки ручной отметки.

## Decisions

- **Соседи считаются во web-слое.** `pages.py` разворачивает
  `sections[].lessons[].steps[]` из ответа `GET /api/v1/courses/{course_id}` в плоский список id и
  берёт предыдущий/следующий. Шаг вне структуры (например, устаревшая ссылка) получает оба
  соседа `None`.
- **Кнопки — ссылки, а на краях — `button disabled`.** Ссылка даёт обычную навигацию и работает
  без JS; на первом/последнем шаге рендерится неактивная кнопка с тем же текстом.
- **Состояние выполнения рендерит шаблон.** Если `step.completed`, форма ручной отметки сразу
  показывает зелёную неактивную «Выполнено»; иначе — активную «Отметить выполненным».
- **JS обновляет кнопку после успешного ответа.** После `POST .../answer` (ручной шаг) кнопка
  получает текст «Выполнено», класс `done` и `disabled`, поэтому повторный запрос невозможен.

## Risks / Trade-offs

- [Дополнительный запрос структуры курса на каждый шаг] → он уже выполняется для заголовка
  страницы, отдельных запросов не добавляется.
- [Названия кнопок без стрелок не очевидны] → добавляем стрелки «← Назад» / «Вперёд →», но текст
  остаётся однозначным.
