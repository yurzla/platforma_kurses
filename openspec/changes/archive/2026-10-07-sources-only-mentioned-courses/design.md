## Context

См. `proposal.md — Why`. После предыдущего изменения `build_sources_section` (`domain/prompts.py`)
перечисляет все курсы найденных чанков. Из-за этого в «Источники» попадают курсы, которых нет в
тексте ответа.

## Goals / Non-Goals

**Goals:**
- В «Источники» — только курсы, упомянутые в ответе (название или ссылка).
- Курс текущей сессии — всегда.
- Нет подходящих курсов — нет секции.

**Non-Goals:**
- Изменение структурированного поля `sources` (оно по-прежнему описывает чанки).
- Определение фактического использования моделью конкретного чанка (используем упоминание курса).

## Decisions

- **Критерий упоминания**: нормализованное название курса (casefold, схлопывание пробелов)
  встречается в ответе, ИЛИ есть Markdown-ссылка `[..](/courses/{id})`. Комбинация «текст или
  ссылка» устойчива: модель может назвать курс без ссылки, либо дать ссылку с иным текстом.
- **`always_ids`**: в `process_question` для сессии по курсу передаётся `{session.course_id}`,
  поэтому текущий курс всегда попадает в «Источники».
- **Порядок**: ответ → `sanitize_course_recommendations` → фильтрация источников → добавление
  секции. Источники считаются по уже очищенному тексту.
- **Пустой результат**: `build_sources_section` возвращает `""`, секция не добавляется.

## Risks / Trade-offs

- [Курс-источник не назван в ответе и не в сессии по курсу] → в «Источниках» его не будет. Это
  ожидаемое поведение варианта B.
- [Ложное совпадение короткого названия в тексте] → нормализованное сравнение по подстроке;
  названия курсов обычно длинные и специфичные.
